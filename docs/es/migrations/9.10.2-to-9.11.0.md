# Guía de migración: 9.10.2 → 9.11.0

Osumi Framework **9.11.0** añade soporte nativo para columnas SQL `DECIMAL(p,s)` en el ORM.

La actualización es compatible hacia atrás y no requiere modificar los modelos existentes.

## Soporte DECIMAL

Los campos `DECIMAL` se representan mediante `OField::DECIMAL` y propiedades PHP `?string`.

```php
#[OField(
	type: OField::DECIMAL,
	precision: 12,
	scale: 2,
	nullable: false
)]
public ?string $amount = null;
```

La representación mediante `string` evita conversiones intermedias a punto flotante y conserva exactamente el valor decimal.

Los valores `float` e `int` no son válidos para campos `DECIMAL`.

La precisión predeterminada es `10` y la escala predeterminada es `2`. La precisión máxima soportada es `65` y la escala máxima es `30`.

Se aceptan `.` y `,` como separadores decimales de entrada. El ORM normaliza siempre el valor a `.` y escala fija:

```text
"12"   → "12.00"
"12.5" → "12.50"
"12,5" → "12.50"
```

El ORM no realiza redondeo automático. Los valores que superen la precisión o escala configuradas producen un error.

`OField::DECIMAL` no puede utilizarse en campos `#[OPK]`.

## Consultas

Las condiciones utilizadas por `where()` y `count()` se validan y normalizan ahora según el esquema del modelo.

Por ejemplo, para un campo `DECIMAL(12,2)`:

```php
Payment::where([
	'amount' => '12,5'
]);
```

utiliza internamente el valor `"12.50"`.

Un valor `float` para ese mismo campo se rechaza:

```php
Payment::where([
	'amount' => 12.5
]);
```

Las condiciones que hagan referencia a campos que no existan en el modelo también se rechazan.

## Generadores

`generateModel`, `generateModelFrom` y `generateModelFromDB` soportan campos `DECIMAL`.

`generateModelFromDB` conserva la precisión, la escala y los valores predeterminados decimales como cadenas exactas.

## Compatibilidad PHP 8.5

La inicialización del esquema ORM comprueba ahora `ReflectionProperty::hasDefaultValue()` antes de llamar a `ReflectionProperty::getDefaultValue()`, evitando el aviso deprecado de PHP 8.5 para propiedades sin valor predeterminado explícito.

## Migración

No existe ningún paso automático de migración para esta versión.

Los proyectos existentes que no utilicen `OField::DECIMAL` no necesitan modificar sus modelos.

Las aplicaciones que comiencen a utilizar `DECIMAL` deben representar estos valores como cadenas exactas y evitar su conversión a `float`.
