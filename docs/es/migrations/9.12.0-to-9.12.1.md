# Guía de migración: 9.12.0 → 9.12.1

Osumi Framework **9.12.1** añade soporte para `CURRENT_TIMESTAMP` como valor por defecto dinámico de campos `DATETIME`.

Esta versión corrige un caso detectado al utilizar `generateModelFromDB` sobre bases de datos reales.

## CURRENT_TIMESTAMP

En 9.12.0, una columna SQL como:

```sql
`joined_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

no podía representarse mediante el ORM.

`generateModelFromDB` detectaba correctamente el campo como `OField::DATETIME`, pero rechazaba `CURRENT_TIMESTAMP` porque los valores por defecto del ORM solo admitían valores literales.

Desde 9.12.1 puede representarse mediante:

```php
#[OField(
	type: OField::DATETIME,
	nullable: false,
	default: OField::CURRENT_TIMESTAMP
)]
public ?string $joined_at = null;
```

Al volver a generar el esquema SQL se conserva la expresión:

```sql
`joined_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
```

## generateModelFromDB

`generateModelFromDB` reconoce ahora las dos representaciones habituales devueltas por MariaDB:

```text
CURRENT_TIMESTAMP
CURRENT_TIMESTAMP()
```

Ambas se convierten en:

```php
default: OField::CURRENT_TIMESTAMP
```

Este soporte está limitado expresamente a campos `OField::DATETIME`.

Las expresiones SQL arbitrarias, como `UUID()`, continúan rechazándose porque el ORM no puede representarlas de forma segura.

## Valores literales

`OField::CURRENT_TIMESTAMP` es un valor especial del ORM.

No debe confundirse con un string literal:

```php
default: 'CURRENT_TIMESTAMP'
```

Un string con ese contenido continúa tratándose como texto normal cuando el tipo del campo lo permite.

## Runtime

Cuando un nuevo modelo tiene un campo `DATETIME` con:

```php
default: OField::CURRENT_TIMESTAMP
```

el ORM resuelve el valor al timestamp actual en formato:

```text
Y-m-d H:i:s
```

al aplicar los valores por defecto antes de guardar el registro.

## Migración

No existe un nuevo paso automático de migración para 9.12.1.

Los modelos existentes de 9.12.0 no necesitan modificarse salvo que representen una columna `DATETIME` cuyo valor por defecto en la base de datos sea `CURRENT_TIMESTAMP`.

En ese caso, `generateModelFromDB` puede regenerar ahora correctamente la definición.

## Actualización

Actualice normalmente mediante Composer:

```bash
composer update osumionline/framework --with-dependencies
```

Después de actualizar puede volver a ejecutar:

```bash
php of generateModelFromDB
```
