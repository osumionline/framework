# Guía de migración: 9.10.1 → 9.10.2

Osumi Framework **9.10.2** corrige el binding de parámetros del ORM para que los valores escalares se envíen a PDO utilizando el tipo de parámetro adecuado.

La actualización es compatible hacia atrás y no requiere modificar el código de las aplicaciones.

## Corrección

Hasta 9.10.1, las operaciones parametrizadas del ORM enviaban directamente el array de parámetros a `PDOStatement::execute()`.

Esto podía provocar que valores booleanos como:

```php
$model->active = false;
$model->save();
```

fueran enviados por PDO como cadenas. En MySQL/MariaDB con modo estricto, `false` podía llegar por tanto a una columna `TINYINT(1)` como una cadena vacía y producir un error como:

```text
Incorrect integer value: '' for column 'active'
```

En 9.10.2, `OModel` realiza el binding explícito de los parámetros antes de ejecutar la sentencia:

- Los valores `bool` usan `PDO::PARAM_BOOL`.
- Los valores `int` usan `PDO::PARAM_INT`.
- Los valores `null` usan `PDO::PARAM_NULL`.
- El resto de valores escalares soportados usan `PDO::PARAM_STR`.

La corrección se aplica de forma consistente a las lecturas y escrituras parametrizadas del ORM, incluyendo consultas, conteos, inserciones, actualizaciones y eliminaciones.

## Migración

No es necesario modificar código de aplicación.

Las definiciones de modelos existentes y las asignaciones booleanas siguen siendo válidas:

```php
$model->active = false;
$model->save();
```

No existe un paso automático de migración para esta versión.
