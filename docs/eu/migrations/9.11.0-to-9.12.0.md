# Migrazio-gida: 9.11.0 → 9.12.0

Osumi Framework **9.12.0** bertsioak SQL `DATE`, `DATETIME` eta `BIGINT` zutabeentzako euskarri natiboa gehitzen du eta `OField::DATE` motaren esanahia birdefinitzen du.

Bertsio honek migrazio-pauso automatiko bat dauka lehendik dauden modeloen bateragarritasuna mantentzeko.

## DATE eta DATETIME

Osumi Framework 9.11 bertsiora arte, `OField::DATE` motak benetan SQL `DATETIME` zutabe bat sortzen zuen.

9.12 bertsiotik aurrera motak bereizita irudikatzen dira:

```text
OField::DATE     → SQL DATE      → PHP ?string → Y-m-d
OField::DATETIME → SQL DATETIME  → PHP ?string → Y-m-d H:i:s
```

Adibidez:

```php
#[OField(
	type: OField::DATE
)]
public ?string $event_date = null;

#[OField(
	type: OField::DATETIME
)]
public ?string $processed_at = null;
```

Denbora-balioak modu zorrotzean balidatzen dira eta existitzen ez diren datak edo baliogabeko orduak baztertzen dira.

`#[OCreatedAt]`, `#[OUpdatedAt]` eta `#[ODeletedAt]` eremuek denbora-zigilu osoak irudikatzen jarraitzen dute eta barnean `DATETIME` erabiltzen dute.

## OField::DATE motaren migrazio automatikoa

9.12 baino lehenagoko bertsioekin sortutako modeloek `OField::DATE` erabiltzen zuten `DATETIME` semantikarekin.

Eguneratzean, `9.12.0` migrazio-pausoak automatikoki hau:

```php
OField::DATE
```

honetara bihurtzen du:

```php
OField::DATETIME
```

`src/Model/` barruko lehendik dauden modeloetan.

Migrazioak benetako PHP kode-tokenak soilik aldatzen ditu eta ez ditu iruzkinen edo testu-kateen barruko agerpenak aldatzen.

Ez du datu-basearen eskema aldatzen: eremu horiek lehendik zuten `DATETIME` semantika mantentzen du.

Migrazioa amaitu ondoren, `OField::DATE` erabilera berriek benetako SQL `DATE` zutabeak adierazten dituzte.

## BIGINT

9.12 bertsioak `OField::BIGINT` gehitzen du.

```php
#[OField(
	type: OField::BIGINT
)]
public ?int $external_id = null;
```

`#[OPK]` atributuan ere erabil daiteke, autoincrement motako lehen mailako gakoetan barne.

`BIGINT` erabiltzeko 64 biteko PHP ingurunea behar da.

`UNSIGNED` eta `ZEROFILL` ez dira onartzen.

## generateModelFromDB

`generateModelFromDB` tresnak mota hauek ezagutzen ditu orain:

```text
DATE     → OField::DATE
DATETIME → OField::DATETIME
BIGINT   → OField::BIGINT
```

SQL `TIMESTAMP` zutabeak baztertzen dira oraindik, ezin direlako ORM-aren `DATETIME` semantikarekin modu fidagarrian irudikatu.

## Pipeak eta formatua

Txantiloietako `date` pipe-ak `DATE` eta `DATETIME` onartzen ditu.

Maskara espliziturik gabe:

```text
DATE     → d/m/Y
DATETIME → d/m/Y H:i:s
```

`OModel::get()` metodoak ere bi denbora-motak onartzen ditu formatu-maskara esplizitu batekin.

## Migrazioen egoera

9.12 bertsioak migrazioen egoera autoritatiboa hemendik:

```text
ofw/tmp/state.json
```

hona eramaten du:

```text
.ofw-migrations.json
```

proiektuaren erroan.

Fitxategi hori aplikazioaren bertsionatutako egoeraren parte da eta Git-en gorde behar da.

9.12 bertsiorako lehen eguneratzean, `.ofw-migrations.json` oraindik existitzen ez bada, runner-ak `ofw/tmp/state.json` irakur dezake azken exekutatutako migrazio-pausoa berreskuratzeko.

9.12 bertsioarekin migrazio bat amaitu ondoren, fitxategi berria bihurtzen da iturri autoritatiboa.

Horri esker, `ofw/tmp/` garbitzeak ezin du nahi gabe migrazio zahar bat berriro exekutatzea eragin.

## Eguneratzea

Eguneratu aurretik, ziurtatu aplikazioaren Git lan-zuhaitza garbi dagoela.

Eguneratu normalean Composer bidez:

```bash
composer update osumionline/framework --with-dependencies
```

`9.12.0` migrazio-pausoa automatikoki exekutatuko da dagokionean.

Eguneratu ondoren:

1. Berrikusi aldatutako modeloak.
2. Gehitu `.ofw-migrations.json` biltegira.
3. Exekutatu aplikazioaren test guztiak.
4. Egiaztatu funtzionalki aplikazioak erabiltzen dituen denbora-eremuak eta BIGINT eremuak.
